---
title: Permission Engine (Equinox)
description: How Strafe.js computes effective member permissions across spaces, roles, room overrides, and threads.
---

`client.resolveMemberPermissions(userId, spaceId, roomId?)` implements the 6-stage Equinox permission calculation.

## 6-Stage Resolution Pipeline

<Steps>
<Step>
### Stage 1: Space Owner Short-Circuit
When `space.owner_id === userId`, the resolver returns `ALL_PERMISSIONS` (`268435455` / `0x0FFFFFFF`).
</Step>

<Step>
### Stage 2: Base Role Permissions
Starts with the `@everyone` role (`space.everyone_role_id`) permission mask and bitwise-ORs (`|=`) the permission masks of all roles listed in `member.role_ids`.
</Step>

<Step>
### Stage 3: Administrator Short-Circuit
When `(mask & Permission.Administrator) !== 0`, the resolver returns `ALL_PERMISSIONS`, bypassing room-level overrides.
</Step>

<Step>
### Stage 4: Room & Thread Permission Overrides
When `roomId` is provided (or inherited from `room.parent_id` for threads without their own overrides), overrides apply in three sub-steps:
1. `@everyone` room override (`role_id === space.everyone_role_id`): `mask = (mask & ~everyoneOverride.deny) | everyoneOverride.allow`.
2. Member role overrides: bitwise-ORs `deny` and `allow` masks across all roles in `member.role_ids`, then applies `mask = (mask & ~aggregatedDeny) | aggregatedAllow`.
3. User-specific override (`user_id === userId`): `mask = (mask & ~userOverride.deny) | userOverride.allow`.
</Step>

<Step>
### Stage 5: Implicit ViewRoom Denial
When `(mask & Permission.ViewRoom) === 0`, the resolver zeroes the entire room mask (`return 0`).
</Step>

<Step>
### Stage 6: Implicit SendMessages Cascade
When `(mask & Permission.SendMessages) === 0`, the resolver clears `Permission.AttachFiles` and `Permission.MentionEveryone`.
</Step>
</Steps>

<Callout title="Thread Permission Rules" type="info">
  Threads (`RoomType.Thread = 6`) inherit their parent channel's role and user overrides when the thread has none of its own. Posting in a thread requires `Permission.SendMessagesInThreads` (`1 << 26`). Private threads (`room.thread?.private === true`) return `0` permissions unless the member is the thread owner, a joined participant, or holds `Permission.ManageThreads` (`1 << 27`).
</Callout>

## Built-In Permission Mask Constants

| Constant | Decimal | Description |
| :--- | :--- | :--- |
| `READ_AND_POST_PERMISSIONS` | `7` | `ViewRoom \| SendMessages \| ReadMessageHistory` |
| `DEFAULT_EVERYONE_PERMISSIONS` | `10723359` | Default `@everyone` role mask on newly created spaces |
| `ALL_ROOM_PERMISSIONS` | `268421071` | All room-scoped flags (excludes `ManageRoles`, `KickMembers`, `BanMembers`, `Administrator`, `ManageSpace`) |
| `ALL_PERMISSIONS` | `268435455` | Bitwise union of all 28 permissions (`(1 << 28) - 1`) |

## Checking Permissions in Commands

Declare required caller and bot permissions on a `command()` definition, or evaluate them at runtime with `ctx.hasPermissions()`:

```ts title="src/commands/kick.ts"
import { command } from '@strafe-js/strafebot';

export default command({
  name: 'kick',
  guildOnly: true,
  permissions: ['KickMembers'],
  botPermissions: ['KickMembers'],
  arguments: {
    target: { type: 'user', required: true },
  },
  async run(ctx) {
    if (!ctx.hasPermissions(['ManageMessages'])) {
      // Optional runtime check inside command handler
    }
    const targetId = ctx.arguments.get('target');
    await ctx.client.rest.kickMember(ctx.spaceId!, targetId);
    await ctx.reply(`Kicked <@${targetId}>.`);
  },
});
```
