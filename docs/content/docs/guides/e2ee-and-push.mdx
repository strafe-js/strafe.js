## End-to-End Encryption (E2EE) & Bot Visibility

Private messages (PMs) and space rooms with `e2ee_enabled: true` use client-side end-to-end encryption. Because bots do not participate in MLS or ratchet key exchange:

- Messages in E2EE rooms arrive over the Gateway and REST API with `ciphertext` populated and `plaintext` omitted.
- Bots cannot decrypt `ciphertext` or send `plaintext` into an E2EE room.

<Callout title="CommandHandler Skips Encrypted Messages Automatically" type="warn">
  When an encrypted message arrives over `MESSAGE_CREATE`, `Client` emits both `messageCreate` and `encryptedMessageCreate`, while `CommandHandler` skips the message because `message.plaintext` is absent.
</Callout>

### Detecting Encrypted Rooms and Messages

Use `isEncryptedRoom`, `isEncryptedMessage`, `client.isRoomEncrypted`, or `ctx.isEncryptedRoom`:

```ts title="src/e2ee-handling.ts"
import {
  Client,
  isEncryptedMessage,
  isSystemMessage,
} from '@strafe-js/strafebot';

const client = new Client({
  apiBase: 'https://app.strafe.chat/api',
  gatewayUrl: 'wss://app.strafe.chat/gateway/events',
});

client.on('encryptedMessageCreate', (message) => {
  console.log(
    `Received encrypted message ${message.id} in room ${message.room_id} from ${message.sender_id}`,
  );
});

client.on('messageCreate', (message) => {
  if (isSystemMessage(message)) return;
  if (isEncryptedMessage(message) || client.isRoomEncrypted(message.room_id)) {
    return;
  }
  console.log('Plaintext message:', message.plaintext);
});
```

## Runtime Space Joins & Session Revocation

<Accordions>
  <Accordion title="How does Client handle being added to a Space while connected (SPACE_CREATE)?">
    When a user installs your bot into a Space while the Gateway connection is open, Stargate dispatches `SPACE_CREATE` with the `Space` object. `Client` caches the Space, calls `GET /spaces/:id/rooms` if `space.rooms` was omitted, caches each `Room`, and sends `op: 1` (`Subscribe`) for the space and its rooms so the bot receives `MESSAGE_CREATE` events without restarting.
  </Accordion>
  <Accordion title="What happens when a bot token is reset (SESSION_REVOKED)?">
    When a bot token is regenerated via `POST /applications/:id/bot/token`, Stargate dispatches `SESSION_REVOKED` (`{ reason: string }`) and closes the WebSocket. `@strafe-js/ws` sets `shouldReconnect = false` and emits `sessionRevoked` so your process can exit cleanly instead of reconnecting with an invalidated token.
  </Accordion>
</Accordions>

## Web Push Notifications (RFC 8291)

User-authenticated sessions can manage Web Push subscriptions (`PUT / PATCH / GET / DELETE /users/@me/push`) using `@strafe-js/rest`:

```ts title="src/push.ts"
import { REST } from '@strafe-js/rest';

const userRest = new REST({
  baseUrl: 'https://app.strafe.chat/api',
  token: process.env.USER_SESSION_TOKEN!,
  authScheme: 'Bearer',
});

const { public_key } = await userRest.getPushVapidKey();

const { subscription } = await userRest.putPushSubscription({
  endpoint: 'https://fcm.googleapis.com/fcm/send/example',
  keys: {
    p256dh: 'BNcRdreALRFXTkOOUHK1EtK2wtaz5Ry4YfYCA_0QTpQtUbVlUls0VJXg7A8u-Ts1XbjhazAkj7I99e8QcYP7DkM',
    auth: 'tBHItJI5svbpez7KI4CCXg',
  },
  kind: 'web',
  prefs: {
    preview: true,
    pm: 'all',
    space: 'mentions',
    calls: true,
  },
});

const testResult = await userRest.testPushSubscription();
console.log(`Delivered: ${testResult.delivered} (status: ${testResult.status})`);
```
